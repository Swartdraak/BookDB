# Contributing to BookDB

Start with [the handbook](BOOKDB_PROJECT.md), the active GitHub issue and [testing](docs/bookdb/08-testing.md). Human and AI contributors use the same issue/branch/PR process.

1. Select a ready issue in the active stage; state observable acceptance criteria.
2. Work in the canonical checkout on a short-lived issue branch. Preserve unrelated changes.
3. Implement a coherent behavior, add meaningful regression/integration tests and update affected docs/contracts.
4. Run the relevant local checks and required CI. Review the staged diff; commit selected paths.
5. Open a PR using the template, link the issue, describe behavior and test evidence. Merge through current rules after successful review/checks.
6. Update issue/Project/milestone state. Human gates require actual human acceptance.

See [GitHub operations](docs/bookdb/09-github-operations.md) for branch, review, ownership, release and Wiki rules. AI contributors also read [AGENTS.md](AGENTS.md). No contributor needs an authority lease or a per-task worktree.

Do not submit copyrighted book text, private reading histories or personal libraries as catalog sources. Retain code notices and source-specific metadata/asset rights. Use the existing license files; source availability is not permission to relicense it.
